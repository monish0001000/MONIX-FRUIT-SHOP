01 · VULNERABILITY BREAKDOWN

Vulnerable Lab

The core issue is trusting data that the browser controls.

!
Client-side price tampering

The quote API calculates the total using item.price from the request. A caller can alter that value before sending the request.

!
Quantity manipulation

Submitted quantity is converted to a number but has no integer, minimum or maximum validation.

!
Missing product / duplicate validation

The handler does not confirm that product IDs exist in the catalogue or reject repeated IDs.

!
No cart or total limits

The quote handler has no explicit item-count, safe-total or maximum-quote checks.

Security concept: business-logic trust failure / parameter tampering. This is a controlled quote-calculation weakness—not SQL injection. The project has no database-backed query.
02 · SECURITY CONTROLS

Secure Store

The server makes the pricing decision and validates the cart before calculating.

✓
Server-authoritative prices

Each accepted product ID maps to a fixed server-side price. Client-supplied prices are never used.

✓
Allowlist + strict quantity checks

Known IDs only; quantity must be a safe integer between 1 and 10.

✓
Duplicate and cart-size protection

Rejects duplicate IDs and requires between 1 and 20 items.

✓
Safe total and origin checks

Checks safe-integer arithmetic, caps quotes at ₹100,000 and rejects a mismatched Origin when supplied.

✓
Browser response hardening

Quote responses use no-store; Vercel config adds CSP and other browser security headers.

Important: these controls harden the demonstrated quote flow. They do not make this demo a complete production e-commerce security system.

About the project

A practical application-security comparison.

MONIX Market is a small, controlled web application built to demonstrate how two applications can look exactly alike while behaving differently at the API layer. The project separates the frontend experience from backend trust decisions so learners can focus on the security controls that matter.

Both storefronts share the same HTML, CSS and JavaScript, the same eight-product synthetic catalogue, and the same responsive shopping experience. They are deployed as separate Vercel projects with independent API implementations. The Project Hub brings the live environments, source code and security explanation together in one place.

Scope, safety & honest limitations

This is an educational demonstration using synthetic catalogue data. Neither deployment has user accounts, a database, persistent carts, order creation, stock management, payment processing or delivery integration. A quote is not an order. The vulnerable endpoint demonstrates client-controlled quote values only; do not describe it as SQL injection or claim a full penetration test has been completed. Use the designated lab for authorized, harmless testing only, and never enter real credentials or personal information.
